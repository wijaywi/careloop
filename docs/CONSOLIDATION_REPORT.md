# Consolidation report

## Scope and archive decision

The human authorized a one-time archive of old or differing CareLoop material.
The archive is outside the project at a local temporary archive location and
is described by an archive manifest and SHA-256 hashes. It is not a project
dependency and is not referenced by shipped code or documentation.

Other unrelated projects were not inspected, modified, moved, or deleted.

## Duplicate/difference comparison

The inspected parent-level CareLoop materials were:

| Location | Result | Evidence/action |
|---|---|---|
| Parent `docs.zip` | 13 files byte-identical to canonical docs; generated registry differed and was older | Hash comparison recorded in the archive; canonical generated registry retained. |
| Parent `files.zip` | Diagram assets only; no application tree | Archived; not moved into the code project. |
| Parent presentation/video files | Submission materials, not runtime dependencies | Archived before any cleanup; excluded from project coding context. |
| Parent `zzztemp` | Design/source fragments and logos; no application tree | Archived; not treated as a runtime dependency. |
| Canonical `web/public/careloop-logo.png` vs `web/dist/careloop-logo.png` | Byte-identical SHA-256 `C0B8...50B1DD6` | Build output is disposable; source asset is canonical. |

The complete machine-readable inventory and hash evidence were written during
the cleanup to the the external archive manifest. No differing file was silently
used to overwrite a canonical file.

## Removed from canonical `out/`

The old `out/` contents were listed and hashed before removal: **41 files**.
They included legacy-named outputs, old checkpoints, runtime logs, prior full
study files, and stale reproduction artefacts. Their hash manifest was saved in
the external archive before the directory was recreated. They were removed
because generated outputs are another version and contained stale code-path
names or results. Current outputs were then regenerated by the consolidated
code.

## Moved

No differing application source was moved into the canonical root. Parent
archives and design assets were archived outside the project, not copied into
the runtime layout.

## Consolidation conclusion

The intended final design has one E1-E9 ledger engine, one canonical loop/case
model, one route set (`/health`, `/demo`, `/cases`, `/audit`, `/analytics`,
`/loops`), one Arm A/B-full naming scheme, and English as the active/default
language segment.

The old full-study result was not preserved as current evidence after the
engine migration. It must be rerun if a full-study claim is needed.
