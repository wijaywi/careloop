# Final report

## What was built

CareLoop is an offline, synthetic-only prototype with:

* a SQLite-backed case service for users, cases, consents, evidence,
  escalations, handoffs, appointments, teach-back records, and audit rows;
* explicit API role filtering and case actions;
* a domain engine with typed entities, legal transitions, stage SLAs,
  requirement stalls, deduplicated escalation rungs, and evidence/human-
  decision closure;
* deterministic English/Arabic communication templates and non-clinical
  teach-back prompts with review flags;
* a paired Arm A/B-full event simulator with segment/pathway metrics,
  sensitivity, stress, intervals, and JSON/CSV output;
* a transport-ledger E1-E9 transport ledger with unknown visibility gaps, urgent and
  routine SLAs, absence reports, typed closure, positive handoff, e-consult,
  result passport, patient-pull, ablation arms, leakage map, and queue policy
  comparison;
* offline tests and a Python 3.11.9/Docker reproducibility path.

## Evidence delivered

The repository test command is:

```text
make test
```

In this documentation pass, the equivalent unittest command ran **36 tests and
passed**. The web typecheck and production build also passed. The commands and
scope are recorded in [EVALUATION_REPORT.md](EVALUATION_REPORT.md).
The simulator is deterministic by construction and has tests that compare
repeated results and the zero-effect paired arms.

## Honest maturity statement

This is a **prototype / hackathon demonstration**, not a validated clinical
product. It has no real-data evaluation, prospective pilot, clinical outcome
measure, production identity system, message-delivery integration, certified
FHIR conformance, security assessment, compliance approval, or commercial
traction evidence. Simulator outputs are conditional on assumption-only
parameters.

## Reproduce

From `APP/` on Python 3.11.9:

```text
python -m venv .venv
.venv\Scripts\activate                 # Windows
# source .venv/bin/activate             # Linux/macOS
python -m pip install -r requirements.lock
make test
PYTHONPATH=. python -m careloop.simulator --cohort-size 1000 --runs 10 --seed 20261019 --json out/smoke.json --csv out/smoke.csv
```

Build/run the container with:

```text
docker build -t careloop-api .
docker run --rm -p 8000:8000 careloop-api
```

No external dataset or network service is needed for these commands.

## Generated output handoff

The bounded reproducibility artefacts are in `out/reproduce.json`,
`out/reproduce.csv`, `out/closure-rate.svg`, and `out/evaluation-table.md`.
They were generated by `python scripts/reproduce.py --output out` with seed
`20261019`, 24 people, 2 runs, and 90 virtual days. The fast smoke artefacts
are in `out/simulate-fast.json` and `out/simulate-fast.csv`. All reported
values are model-conditional and use assumption-only parameters.

The transport-ledger bounded artefact is `out/reproduce.json` with its CSV companion.
It contains Arm A, B-full, four ablations, 95% replication intervals,
stress scenarios, typed closure distributions, unknown rates, uncertainty
hours, leakage map, and FIFO/priority workload comparison.

## Sensitivity conclusion

The transport-ledger bounded run produced fourteen one-at-a-time parameter sweeps and
eight deterministic Latin-hypercube points. In the configured transport-ledger
stress scenarios, B-full remained above Arm A in this run: cross-provider
dominant (`0.7500` vs `0.5834`), e-consult unavailable (`0.7500` vs
`0.5834`), insufficient staff (`0.7500` vs `0.5834`), poor contact data
(`0.5417` vs `0.4583`), and rare reporting (`0.7500` vs `0.5834`). The global
sample's B-full closure-rate range was `0.1666` to `0.4583`. This is a
conclusion about the behavior of this workflow model only; it does not
establish clinical effectiveness and should not be generalized beyond the
parameterized scenarios.

## Provenance counts

The transport-ledger registry contains **72 `assumption` records and 0 `sourced`
records**. Every current source is `not yet found / assumption`. No literature
parameter was promoted to `sourced` without a verified source.

The selected primary scenario is **abnormal mammogram requiring diagnostic
imaging or biopsy**. Stage 9 treatment/surveillance start is configured as an
operational assumption of 14 days urgent and 30 days routine. This value is not
presented as a verified clinical guideline.

## Not completed in this prototype

The core full 10,000 × 500 study was executed with the checkpointed runner for
Arm A and B-full. Its result is in `out/full-study-core/result.json` and its
generated report is `out/full-study-core/report.md`. The six-arm ablation study
was not run at full scale; ablations remain verified at bounded scale. No real
FHIR conformance, production identity,
clinical validation, native-speaker translation approval, security assessment,
or real-provider integration was completed. The browser UI now calls the V2 API
through the local proxy and falls back to local synthetic state when unavailable;
production identity propagation is not included. `make`/WSL was intentionally
skipped at the user's request, so the equivalent Windows commands are the
executed evidence.
